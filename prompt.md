## 1. Product summary
Call centers currently QA by picking 1-2 random calls per employee per month. Arocall records every call through a lightweight background desktop app on the employee's computer, transcribes it with speaker labels, scores it against the company's QA policy with evidence, and shows everything in a web dashboard. After an evaluation period, the admin can send the employee to a live voice coaching session with an AI agent instead of a human evaluator.

Supported call languages: English, French, German, Spanish. The AI coaching session is English only for now. The dashboard UI is English only.

## 2. Components to build
A) Web dashboard (admin/evaluator facing)
B) Backend API + processing pipeline
C) Background desktop agent (employee machine)
D) AI coaching session (voice call with an AI coach)

## 3. Web dashboard requirements
Auth
- Email + password signup/login and "Continue with Google" login.
- Each signup creates an Organization; the first user is its admin. Admins can invite evaluators (email invite).
- Roles: admin, evaluator (read + coaching trigger), employee (optional, read-only own profile; can be skipped for MVP if time is short).

Onboarding + walkthrough
- First-login guided walkthrough (step-by-step, skippable, re-openable from a Help menu): 1) upload or paste the QA policy, 2) add the first employee, 3) copy the session key, 4) install the desktop agent and paste the key, 5) see the first call appear.
- Empty states throughout that point to the next step.

Employees
- Create/edit employees: name, photo, department, languages worked, start date.
- Each employee gets a unique Session Key (long random string, shown once at creation, copyable, regenerable/revocable by admins; store only a hash server-side). The key identifies the employee for the desktop agent.
- Employee list as cards: photo, name, department, languages, overall score with a colored indicator, trend arrow vs previous period.

Employee profile page (social-profile style)
- Header: photo, name, department, languages, overall score, score trend graph over time, strengths and weaknesses summary generated by AI.
- Below: a table of calls (date, duration, language, score, status). Clicking a row opens Call Detail.
- Filters by date range, language, score range.

Call Detail page
- Audio player (seekable).
- Transcript with speaker labels (Agent / Customer) and timestamps; clicking a line seeks the audio; evidence quotes from the report link to their transcript line.
- AI report: overall score, per-criterion pass/fail/partial with a score, the exact quoted transcript line and timestamp as evidence, a short summary, what went well, what went wrong, and tags (for example: greeting, empathy, compliance, upsell, closing).
- Button to re-run analysis (e.g. after the policy changes).

QA policy / scorecard
- Admin uploads a document (PDF/DOCX/TXT) or pastes text. The AI converts it into a structured scorecard: a list of criteria, each with a description, weight, and pass/fail guidance. The admin can review and edit the criteria before saving. Versioned: each call stores which scorecard version scored it.

Coaching memos
- For an employee and a date range, generate a coaching memo: summary of performance, improvements since last period, top 3 issues with evidence quotes from specific calls, concrete action plan, and suggested practice phrases. Exportable as a clean printable PDF. Evaluators can edit before exporting.

Coaching sessions (AI coach)
- From an employee profile, the admin clicks "Start AI coaching session" and optionally attaches the memo and focus topics. The employee receives a link (email or copy link).
- See section 6 for the session itself. After the session, store the transcript, an AI summary, and agreed action items on the employee profile.

## 4. Backend and processing pipeline
- Endpoint for the desktop agent to authenticate with the session key and upload call audio (chunked/resumable upload) with metadata (start/end time, device, whether channels are separate).
- Audio arrives as two tracks per call (mic = Agent, system/speaker output = Customer) or as one stereo file with Agent on the left channel and Customer on the right. Speaker labels come from channel identity, not from ML diarization.
- Pipeline (queue-based, async, with retries and status per call: uploaded, transcribing, analyzing, done, failed):
  1. Store audio in object storage.
  2. Transcribe each channel separately with a speech-to-text model that supports en/fr/de/es with automatic language detection; merge by timestamps into one speaker-labeled transcript.
  3. Send the transcript plus the active scorecard to the Muse model. Require structured JSON output validated against a schema. Every criterion result MUST include a verbatim evidence quote and timestamp from the transcript. Reject and retry if the quote is not found in the transcript.
  4. Compute the call score from the criterion weights in code, not in the LLM.
  5. Update the employee's rolling overall score and trend data.
- Make scoring deterministic where possible (low temperature, fixed prompts, versioned prompt files).
- Seed script: create a demo organization with 5 employees and about 40 pre-made synthetic calls (transcripts plus a few audio files), including one employee who clearly improves over time and one who declines, so the dashboard looks meaningful on first launch.

## 5. Desktop agent (Windows first; macOS if time allows)
- Tiny background app, no main window. Runs from a system tray icon (status: connected / recording / error) with a minimal menu: Enter session key, Status, Quit disabled unless admin password is entered.
- First run: a small window asking for the session key. Paste, validate against the server, save into a local config file (stored with the key encrypted using the OS credential store). Afterwards the app starts silently. The key can only be changed by editing the config or re-running setup with admin confirmation.
- Starts automatically on login/boot and restarts itself after crashes (auto-restart watchdog).
- Captures two audio streams: microphone input (Agent) and system output loopback (Customer; on Windows use WASAPI loopback). Detect call start/end by activity thresholds on both streams plus silence timeout; do not record when no call is active.
- Saves audio locally in a small encrypted buffer, uploads in the background, retries when offline, and deletes local files after successful upload.
- Shows a visible recording indicator and a one-time consent notice at install. Include configuration for an optional "call recording notice" reminder text. Do not hide the existence of the app from the employee.
- Package as a signed installer if feasible, otherwise a plain installer plus a README.

## 6. AI coaching session
- A web page the employee opens from a link. Pre-join screen: mic/speaker check, short explanation that this is an AI coach and that the session is recorded and summarized.
- In-session: real-time voice conversation (speech-to-text in, Muse model reasoning, text-to-speech out) with low latency, interruption handling, and a live captions panel. Show the avatar or animated waveform for the AI coach.
- The coach's system prompt is built from: the employee's recent scores, the memo, specific call evidence, and the company policy. Tone: supportive, specific, and honest. It must reference real examples from the employee's calls, ask the employee for their perspective, role-play one difficult customer scenario with them, and end by agreeing on 2-3 concrete action items.
- Safety rules for the coach: it must not make employment decisions (no firing, warnings, pay, or promotion statements), must not invent facts about calls, and must offer to flag the conversation to a human evaluator when the employee raises complaints, harassment, health, or personal issues. Add a "Request human evaluator" button.
- English only for now, but build it so that adding other languages later is a config change.
- Stretch goal (only after everything else works): run the same coach inside Google Meet. Note that Meet has no simple bot API for this, so isolate it behind an interface and document what is needed. The in-app session is the primary implementation.

## 7. Data model (adapt to the stack)
Organization, User (role), Employee (name, photo, department, languages, session_key_hash, status), Scorecard (version, criteria[] with weight and guidance), Call (employee, started_at, duration, language, audio_url(s), status, transcript, score, scorecard_version), CriterionResult (call, criterion, result, score, evidence_quote, timestamp), Memo (employee, period, content, pdf_url), CoachingSession (employee, memo, transcript, summary, action_items, human_flag).

## 8. Non-functional requirements
- Privacy and compliance: all data scoped per organization (strict multi-tenant isolation), encryption in transit and at rest, signed expiring URLs for audio, audit log of who played or exported a call, configurable retention period, and a deletion option for an employee's data. Add a clear "AI assists, humans decide" notice in the UI. No automated disciplinary actions.
- Fairness: show evidence for every score; never display a score without its supporting quotes.
- Responsive, clean, modern UI with a professional look (light theme, a blue/teal accent), loading and error states everywhere.
- Environment variables for all keys, a .env.example, and a README with setup steps for the web app, backend, and desktop agent.
- Basic tests for the scoring pipeline (schema validation, evidence-quote verification, weighted score calculation).
